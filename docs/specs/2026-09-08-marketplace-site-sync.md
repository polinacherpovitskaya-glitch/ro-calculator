# Надёжная передача B2C-наборов на сайт

**Дата:** 2026-09-08  
**Статус:** implementation ready  
**Область:** B2C-наборы в калькуляторе и общий каталог `marketplace_sets`

## Проблема

Сайт `recycleobject.ru` получает список для поля «Калькулятор» из общей таблицы
`marketplace_sets`. Калькулятор при недоступности базы записывал набор только в
локальное хранилище браузера, но всё равно показывал сообщение «Набор сохранён».
Из-за этого набор был виден автору в калькуляторе, однако не появлялся на сайте и
не мог быть привязан к товару.

## Цели

- Считать сохранение набора успешным только после подтверждения общей базы.
- Безопасно повторять временно неудавшуюся запись: `upsert` использует один и тот
  же идентификатор набора и не создаёт дублей.
- Оставлять форму и введённые данные на экране, если общая база недоступна.
- Явно сообщать пользователю, что данные не синхронизированы и сохранение нужно
  повторить.
- Не ломать локальный режим разработки без настроенного Supabase.

## Решение

1. В `saveMarketplaceSet` выполнять до двух попыток `upsert` с короткой паузой.
2. При ошибке обеих попыток выбрасывать исключение и не обновлять локальный кэш
   как будто запись была подтверждена.
3. В форме набора перехватывать ошибку, сохранять введённое состояние на экране и
   показывать понятное сообщение.
4. Для редактирования цен в карточке показывать статус «не сохранено» и оставлять
   новую цену для повторной попытки.

## Инварианты

- Схема `marketplace_sets` и формат `set_data` не меняются.
- Сигнатура `saveMarketplaceSet(mset)` сохраняется.
- Успешная запись по-прежнему обновляет локальный кэш.
- В полностью локальном режиме наборы по-прежнему сохраняются в браузере.

- `node tests/version-smoke.js`

## Вне области

- Изменение товарного каталога сайта.
- Миграция схемы базы.
- Автоматическая публикация или создание товара на сайте из калькулятора.
- Исправление временных ошибок загрузки изображений в админке сайта; это отдельное
  парное изменение в репозитории `recycle-object-site`.
