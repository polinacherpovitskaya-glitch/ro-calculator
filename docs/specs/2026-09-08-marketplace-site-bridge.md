# Мост цен между калькулятором и сайтом

**Дата:** 2026-09-08  
**Статус:** implementation ready  
**Область:** B2C-наборы калькулятора и каталог `recycleobject.ru`

## Проблема

После отказа калькулятора от Supabase его B2C-наборы сохраняются в
`compat_rows` собственного API. Сайт продолжает хранить товары в отдельной
базе `db.recycleobject.ru` и читает старую таблицу `marketplace_sets`.
Поэтому новые наборы видны в калькуляторе, но отсутствуют в поле
«Калькулятор» на сайте и не могут передавать ему актуальную цену.

## Решение

- Добавить в API калькулятора публичный read-only каталог B2C-наборов.
- Отдавать только `id`, `name`, `shop_actual_price` и `updated_at`; состав,
  себестоимость и внутренние поля не публиковать.
- На сайте использовать этот каталог для выбора набора, отображения цены и
  серверной проверки цены заказа.
- При временной недоступности API сохранить fallback на старую таблицу и
  ручную цену товара.

## Инварианты

- Товар сайта продолжает хранить связь в `marketplace_set_id`.
- Цена связанного товара берётся из `shop_actual_price`; поле `products.price`
  остаётся запасной ценой.
- Запись наборов остаётся авторизованной; публичным является только
  ограниченный каталог для чтения.
