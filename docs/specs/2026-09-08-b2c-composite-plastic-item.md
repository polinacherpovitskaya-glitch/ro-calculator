# Составное пластиковое изделие в B2C

## Контекст

Некоторые готовые товары состоят из нескольких пластиковых деталей, которые
проливаются в отдельных молдах. Например, брелок-кликер состоит из основы и
звёздочки. Сейчас карточка B2C умеет хранить несколько пластиковых строк и
суммирует их себестоимость, но не объясняет этот сценарий пользователю. При
создании производственного заказа каждая строка также превращается в отдельное
изделие, поэтому количество готовых товаров и производительность отображаются
неверно.

## Цель

Дать пользователю явную возможность объединить несколько пластиковых молдов в
одну готовую товарную позицию. Для составного изделия калькулятор должен:

- суммировать материалы, амортизацию, ФОТ и косвенные расходы всех деталей;
- учитывать количество каждой детали на одно готовое изделие;
- складывать время отдельных проливок;
- создавать в производственном заказе одну позицию готового изделия на каждый
  цветовой вариант;
- сохранять внутри позиции перечень молдов, их нормы, цвета и количества.

## Пользовательский сценарий

В форме набора B2C рядом с пластиковыми элементами появляется переключатель
«Объединить пластиковые части в одно готовое изделие». Пользователь добавляет
молд основы и молд звёздочки, задаёт по одной детали каждого вида и включает
переключатель. Под составом сразу показываются обе нормы и расчётная
производительность готового изделия.

Для нового набора режим включён по умолчанию. Для существующих наборов он не
включается автоматически, чтобы не менять структуру уже настроенных
производственных заказов без явного решения пользователя.

## Расчёт производительности

Поскольку детали проливаются отдельно, время на одну готовую единицу
складывается:

`часы на единицу = Σ(количество детали / производительность молда)`

`готовых единиц в час = 1 / часы на единицу`

Для основы 60 шт/ч и звёздочки 45 шт/ч:

`1 / (1 / 60 + 1 / 45) = 25,71 готового кликера/ч`

Это значение описывает последовательную загрузку производства. Полные часы
заказа продолжают рассчитываться отдельно по каждому молду, включая запас на
брак и подготовку цвета, а затем суммируются.

## Хранение данных

- В записи набора сохраняется булево поле `composite_plastic_item`.
- Состав по-прежнему хранится в существующем `plastic_items`; миграция базы не
  требуется.
- В объединённой позиции заказа сохраняется
  `marketplace_plastic_components` с идентификаторами молдов, названиями,
  количеством, нормой и цветом. Поле попадает в существующий `item_data`.

## Совместимость

- Наборы с одним пластиковым элементом работают как раньше независимо от
  переключателя.
- Существующие наборы без `composite_plastic_item` продолжают создавать
  отдельные производственные строки.
- Фурнитура, упаковка, цветовые варианты и публикация цены на сайт не меняются.

## Критерии готовности

- Переключатель сохраняется и восстанавливается при редактировании набора.
- При двух деталях 60 и 45 шт/ч интерфейс показывает 25,71 готового изделия/ч.
- Себестоимость готовой позиции содержит стоимость обеих деталей.
- Производственный заказ содержит одну пластиковую позицию с количеством
  готовых изделий, но его часы литья равны сумме часов двух проливок.
- Обычные и исторические B2C-наборы проходят прежние smoke-тесты.
