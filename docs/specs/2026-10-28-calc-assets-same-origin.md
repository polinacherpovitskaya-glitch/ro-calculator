# Калькулятор грузит свой код с сервера, а не из старого бакета

## Что случилось
После мёржа PR #311 (v482) деплой отчитался успехом, а живые смоуки упали: страница
показывала v482, но код работал v481.

Сборка (`scripts/build-yandex-static.mjs`, функция `rewriteIndexForObjectStorage`) переписывала
все относительные ссылки на скрипты и стили в `index.html` на
`https://storage.yandexcloud.net/calc.recycleobject.ru/...`. Так было нужно, пока калькулятор жил
в бакете. С PR #309 калькулятор раздаёт сервер (Caddy, релизы в `~/srv/static/releases`), а бакет
больше не обновляется и застыл на v481. Новая страница с сервера тянула старый код из бакета.

Шаг деплоя «Verify published calculator version» проверял только `js/version.json` на сервере,
поэтому поломку не заметил.

## Что должно получиться
1. `index.html` в релизе ссылается на скрипты и стили относительно, и сервер отдаёт их из того же
   релиза. Сборка копирует `index.html` без изменений.
2. Деплой после переключения релиза проверяет и `js/version.json`, и тот `js/app.js`, который
   реально грузит опубликованная страница: ссылка должна быть относительной, а `APP_VERSION`
   совпадать с `js/version.json`. Иначе деплой красный с понятным сообщением.
3. Тест `tests/single-calculator-deploy-smoke.js` не даёт вернуть ссылку на бакет в сборку и
   убрать проверку `APP_VERSION` из деплоя.

## Не делаем
- Версию приложения не поднимаем: код SPA не меняется, на сайт должна доехать та же v482.
- Заголовки кэша Caddy на сервере (`/` сейчас отдаётся с `immutable` на год, потому что правило
  `*.html` не совпадает с `/`). Конфиг Caddy живёт только на сервере, не в этом репозитории, —
  меняется отдельно с согласия Полины.
- Бакет `calc.recycleobject.ru` не трогаем.
