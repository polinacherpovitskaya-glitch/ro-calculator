# Timebot: отчёты за несколько дат

## Проблема

Сотрудник может перечислить задачи за несколько дней одним сообщением, используя
заголовки дат:

```text
24.07:
Проект / Этап — 1ч

27.07:
Проект / Этап — 2ч
```

Когда такое сообщение отправляется на обязательном шаге комментария, бот сохранял
все уже выбранные задачи на текущую дату. В результате часы за 24 июля попали в
27 июля.

## Требуемое поведение

- Бот распознаёт заголовки `ДД.ММ:` и `ДД.ММ.ГГГГ:`.
- Каждая следующая строка задачи получает дату ближайшего предыдущего заголовка.
- Формат с датой в каждой строке продолжает работать.
- Много-дневный отчёт распознаётся на любом шаге диалога, включая обязательный
  комментарий.
- Неполный обычный комментарий с датой не считается пакетным отчётом.
- Существующая защита от дубликатов и резервная очередь сохраняются.

## Границы

- Схема `time_entries` не меняется.
- Публичные API модулей калькулятора не меняются.
- Исправление уже ошибочно датированных производственных строк выполняется
  отдельно точечным обновлением данных.

## Приёмка

- Пример выше создаёт строки на 24 и 27 июля соответственно.
- Старый формат `24.07 — Проект / Этап — 1ч` проходит без регрессии.
- Текст `24.07:\nОбычный комментарий` остаётся обычным комментарием.
- Версия приложения повышена до `v419`.
