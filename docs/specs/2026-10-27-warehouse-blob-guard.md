# Склад: резервы, история, галочки «собрано», готовые изделия без потерь

## Проблема

Резервы (`warehouse_reservations.reservations_data`), история склада
(`warehouse_history.history_data`) и галочки «собрано»/факт. количества
(`settings.project_hardware_state_json`) хранятся **одной строкой** и сохраняются **целиком** из
того, что вкладка когда-то загрузила. Сервер делает upsert без проверки версии → «последний
затирает всех»:

- при таймауте загрузки (5 с) вкладка берёт bootstrap-снимок (до ~30 мин) или localStorage и
  сохраняет его как истину — пропадают свежие резервы/записи истории других людей;
- `this.projectHardwareState` грузится один раз за сессию, а сохраняется при каждом сохранении
  заказа — галочки склада, проставленные позже, откатываются;
- `reconcileProjectHardwareReservations` (на каждое открытие склада) при неполной загрузке
  заказов/позиций снимает галочки и резервы заказов, которых «не увидел»;
- кнопка «Сохранить» в Настройках переписывает `project_hardware_state_json` из `App.settings`;
- `_loadReadyGoodsStore` при таймауте/ошибке считает данные «не существующими» и записывает `[]`
  в остатки, историю и продажи готовых изделий.
- потерянные записи истории ломают расчёт «уже списано» → повторные списания.

## Решение

### A. Сервер: атомарный патч блоба `POST /api/compat/blob-patch`
Белый список целей: `warehouse_reservations`, `warehouse_history` (записи с `id`),
`project_hardware_state` (карты `checks`, `actual_qtys`, … + верхние поля).
- записи: `upserts` (замена по `id` на месте, новые — в начало/конец), `removeIds`;
- карты: `set{map:{k:v}}`, `remove{map:[k]}`, `top{k:v}`;
- под advisory-lock таблицы, читает одну строку, применяет, пишет, возвращает итоговое значение.
- резервы: после слияния для активных `source: 'project_hardware'` по паре (заказ, позиция)
  остаются только самые свежие (`created_at`), старые помечаются `released` — защищает от
  задвоения, когда две вкладки одновременно пересчитали резервы.

### B. Клиент: сохранять разницу, а не весь блоб
`saveWarehouseReservations/History`, `saveProjectHardwareState` сравнивают сохраняемое с тем,
что было загружено (снимок на каждую загруженную запись/объект), и отправляют только изменения.
Удаление — только для записей, которые вкладка реально загрузила и убрала. Сигнатуры функций
не меняются, ~40 вызовов в warehouse/orders/app не трогаем. 404/405 (API ещё не задеплоен) →
старая запись целиком.

### C. Точечные защиты
- reconcile ничего не пишет, если заказы или их позиции не загружены целиком с сервера;
- `project_hardware_state_json` исключён из глобальных настроек и никогда не пишется
  через `saveAllSettings`;
- готовые изделия: «пусто» записывается только когда настройки действительно нет;
  при ошибке/таймауте раздел показывает «временно недоступна» и ничего не пишет.

## Не входит
- Остатки `warehouse_items` (абсолютные qty), сотрудники, закупки Китая — отдельные PR.
- Конкурентные правки готовых изделий (сохранение целиком) — отдельно.
