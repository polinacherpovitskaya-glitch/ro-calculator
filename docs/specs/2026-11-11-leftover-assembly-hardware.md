# Сборка из остатков + фурнитура со склада

## Проблема

Алина (PM) собирает 53 обвеса: пластик — готовые буквы-излишки прошлых проектов
(не льём, не числятся на складе), фурнитура — со склада. Ни один тип работ не подходит:

- «Клиентский заказ» требует изделие с литьём (пластик, молд, запуск).
- «Сборка из неучтённых остатков» (`leftover_assembly`) скрывает раздел
  «Фурнитура и упаковка» и при сохранении выбрасывает все строки
  (`_collectItemsForSave` → `[]`). Фурнитура не резервируется, не списывается и
  не попадает в себестоимость — маржа завышена.

## Решение

Не вводим новый тип. В режиме «Сборка из остатков» показываем раздел
«Фурнитура и упаковка» и учитываем его:

- **Пластик/детали остатков** — как раньше: бесплатно, описание текстом.
- **Фурнитура и упаковка** — обычные строки (склад / Китай / своя). Сохраняются
  как `hardware`/`packaging` строки заказа без родителя → складская синхронизация
  (`Warehouse.syncProjectHardwareOrderState`) резервирует и списывает их как в
  любом заказе.
- **Часы** = «Доп. ручная сборка, ч» (ручное поле, бывшее «Ручная сборка») +
  нормы фурнитуры и упаковки из их строк.
- **Себестоимость** = косвенные × все часы + закупка и доставка фурнитуры/упаковки.
  Прямую зарплату по-прежнему не начисляем (сборщики в косвенных).
- **Выручка** — по-прежнему одно поле «Продажа без НДС, ₽ (всего)»; цены продажи
  у строк фурнитуры в этом режиме не используются.

Заказы без фурнитуры считаются ровно как раньше.

## Затрагиваемые места

- `js/calculator.js` — `calculateLeftoverAssemblyLoad/Summary/FinDirector`
  принимают строки фурнитуры/упаковки (живые или сохранённые);
  `getOrderLiveCalculatorSnapshot` передаёт их из `order_items`.
- `js/app.js` — раздел фурнитуры не скрывается; сохранение отдаёт строки
  фурнитуры/упаковки; карточка цены показывает материалы.
- `js/orders.js` — список заказов считает снапшот с позициями.
- `index.html` — тексты панели.

## Вне рамок

- Отдельный тип «готовый пластик со скидкой» и учёт букв-излишков на складе.
- Привязка фурнитуры к изделиям (изделий в режиме нет — всё «общее»).
- Изменения схемы БД: поля и строки уже существуют.
