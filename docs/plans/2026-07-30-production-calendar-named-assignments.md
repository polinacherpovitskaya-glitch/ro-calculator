# Plan — Именные назначения в производственном календаре

**Spec:** `docs/specs/2026-07-30-production-calendar-named-assignments.md`  
**Created:** 2026-07-30  
**Status:** Completed

## Execution analysis

- Задача разделена на две волны: сначала именной план, затем закрытие смены.
- Волна A не требует миграции БД: сотрудники уже загружаются из `employees`,
  а назначения и цвета можно добавить в `production_plan_state_json`.
- Дневные часы можно показать сразу из готового schedule.
- Дневные штуки допустимы только для заказов с надёжными
  `production_quantity` и плановыми часами этапа.
- Вечерний факт намеренно не входит в этот PR: сначала нужно подтвердить на
  реальных заказах, что плановая норма в штуках не вводит цех в заблуждение.

## Assumptions

- Канонический состав календаря — выбранные активные сотрудники из «Часов»;
  production-сотрудники идут первыми, но роль не исключает человека из выбора.
- При ровно четырёх сотрудниках отдельная первоначальная настройка не нужна.
- Ручное назначение является жёстким; автоматическое — свободно
  перераспределяется после изменения очереди.
- Верхняя очередь и выдвижная панель удобнее постоянной левой колонки.
- Текущая модель человеко-часов остаётся источником прогнозных дат.

## M1. Уникальная визуальная идентичность заказов `[x]`

### Goal

Каждый видимый заказ узнаваем по собственному акценту, а соседние заказы не
сливаются.

### Tasks

- [x] Добавить нормализацию `order_color_slots`.
- [x] Построить детерминированную карту цветов для текущей очереди.
- [x] Исключить повтор цвета среди видимых заказов.
- [x] Максимизировать дистанцию между четырьмя ближайшими заказами.
- [x] Использовать одну карту в очереди, полосах, скобах и дедлайнах.
- [x] Добавить smoke fixtures для очереди длиннее старой палитры.

### Definition of done

- Десять и более соседних заказов имеют разные акценты.
- Перестановка двух заказов не меняет их собственные цвета.
- Этапы остаются узнаваемыми по текущим цветам заливки.

### Validation

```sh
node --check js/gantt.js
node tests/production-calendar-smoke.js
```

### Known risks

- Слишком светлый сгенерированный цвет может потерять контраст.

### Stop-and-fix rule

- Не переходить к новой компоновке, пока fixture не доказывает уникальность и
  минимальный контраст.

## M3. Состав команды и именные назначения `[x]`

### Goal

Каждая линия принадлежит реальному сотруднику, а начальник производства
назначает конкретных людей.

### Tasks

- [x] Передать employees в модель отображения, а не только в расчёт факта.
- [x] Нормализовать `roster_employee_ids` и `employee_assignments`.
- [x] Автоматически выбрать до четырёх активных сотрудников, отдавая
  production-сотрудникам приоритет.
- [x] Добавить выбор состава, если активных сотрудников больше или меньше.
- [x] Заменить `Человек 1–4` именами и дневными часами.
- [x] Добавить `Авто` и ручные чипы исполнителей в очередь.
- [x] Синхронизировать ручное количество с `parallel_workers`.
- [x] Обновить scheduler: worker slot получает стабильный `employeeId`.
- [x] Зафиксировать ожидание закреплённого занятого сотрудника.
- [x] Помечать невалидное назначение как требующее переназначения.

### Definition of done

- Можно назначить один заказ двум конкретным людям.
- Другие два человека получают следующие заказы по очереди.
- На каждой именной линии отсутствуют пересечения.
- После reload имена, порядок линий и ручные назначения сохраняются.

### Validation

```sh
node --check js/production-core.js
node --check js/gantt.js
node tests/production-calendar-smoke.js
node tests/employee-auth-payroll-smoke.js
```

### Known risks

- Старые cached employees могут кратко отобразиться до удалённого обновления.
- Неактивный сотрудник может остаться в сохранённом назначении.

### Stop-and-fix rule

- Любое пересечение именной линии или тихая подмена ручного исполнителя
  блокирует переход к дневным нормам.

## M4. Дневные часы и безопасная норма в штуках `[x]`

### Goal

Сотрудник без расчётов понимает своё сегодняшнее задание.

### Tasks

- [x] Суммировать сегодняшние интервалы по сотруднику, заказу и этапу.
- [x] Показывать плановые часы рядом с именем и в сегодняшнем баре.
- [x] Рассчитать плановые штуки из `production_quantity` и часов этапа.
- [x] Распределить округление без превышения количества заказа.
- [x] Выключать штуки для неоднозначных или неполных данных.
- [x] Показывать `Нужна норма` вместо ложного числа.
- [x] Добавить структуру `daily assignment`, пригодную для следующей волны
  закрытия смены, без сохранения факта.

### Definition of done

- На однородном заказе видно `9 ч · план N шт.`.
- На неоднозначном заказе видно время и честный статус отсутствия нормы.
- Сумма плановых единиц этапа не превышает количество заказа.

### Validation

```sh
node --check js/production-core.js
node --check js/gantt.js
node tests/production-calendar-smoke.js
```

### Known risks

- Агрегат `production_quantity` может быть недостаточно точным для заказа с
  несколькими разными изделиями.

### Stop-and-fix rule

- При сомнительной структуре заказа скрыть штуки, а не выпускать приблизительное
  число без маркировки.
