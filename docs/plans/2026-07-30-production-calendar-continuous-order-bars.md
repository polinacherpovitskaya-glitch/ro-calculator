# Plan — Continuous production order bars

**Spec:** `docs/specs/2026-07-30-production-calendar-continuous-order-bars.md`
**Created:** 2026-07-30
**Status:** In progress

## Milestone 1 — Зафиксировать строгий приоритет

- [ ] Добавить fixture: верхний заказ на двух линиях, второй на третьей,
  третий на четвёртой.
- [ ] Добавить fixture: верхний заказ на четырёх линиях блокирует старт
  нижних заказов.
- [ ] Проверить отсутствие пересечений на каждой линии после освобождения
  сотрудника внутри смены.

**Gate:** точное распределение первой волны соответствует очереди, а не только
общему числу одновременно стартовавших заказов.

## Milestone 2 — Сгруппировать дневные интервалы

- [ ] Построить `order runs` для одной линии из последовательных schedule
  сегментов заказа.
- [ ] Объединить соседние рабочие дни в одну оболочку.
- [ ] Сохранить внутренние секции этапов и незалитые разрывы выходных.
- [ ] Добавить вычисление фактически одновременной команды заказа.

**Gate:** длинный заказ имеет одно название и один внешний контур на каждой
занятой линии.

## Milestone 3 — Сделать проекты и команды читаемыми

- [ ] Добавить стабильную палитру проекта независимо от цвета этапа.
- [ ] Нарисовать связанные полосы и вертикальную скобу для 2–4 людей.
- [ ] Показывать название, номер, индекс человека, готовность и этапы без
  повторения по дням.
- [ ] Связать дедлайн с цветом и названием проекта.
- [ ] Ослабить затемнение остальных заказов при наведении.
- [ ] Заменить двусмысленное `до N` на компактное `N чел.`.

**Gate:** без подсказок можно определить, какие линии заняты одним заказом,
где его этапы и когда он должен быть готов.

## Milestone 4 — Проверить и выпустить

- [ ] Обновить production-calendar smoke под новый DOM-контракт.
- [ ] Прогнать сценарии `1 → 2 → 3 → 4 человека` в реальном браузере.
- [ ] Проверить week/month zoom и узкую/широкую очередь.
- [ ] Запустить syntax, production-calendar, order-flow и version smokes.
- [ ] Выбрать следующую версию от актуального `origin/main` и обновить четыре
  version anchor плюс cache-bust изменённых runtime-файлов.
- [ ] Проверить diff на случайные изменения схемы, API и пользовательских
  файлов.

**Gate:** автоматические и визуальные проверки проходят, версия согласована во
всех anchors.

## Rollback

Откатить frontend-коммит этой волны. Миграция БД и преобразование сохранённого
плана не требуются.
